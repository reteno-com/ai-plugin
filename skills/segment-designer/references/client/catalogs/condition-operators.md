# Segment Condition Operators

| Group | Operator pattern | Options | Functionality | Value guidance |
| --- | --- | --- | --- | --- |
| Comparison | `BETWEEN` | - | Matches values inside the supplied range. Numeric ranges include both boundaries; date and date-time ranges cover the selected end date or minute. | Use `lower,upper` in ascending order. Numeric values use the field's scalar format. Dates use `DD/MM/YYYY,DD/MM/YYYY`; date-times use `DD/MM/YYYY HH:mm,DD/MM/YYYY HH:mm`. |
| Comparison | `GREATER_THAN`, `LESS_THAN` | - | Matches values strictly greater than or strictly less than the supplied scalar on fields that support ordered comparison. | Use one scalar matching the field. Dates may be `DD/MM/YYYY`; date-times may be `DD/MM/YYYY HH:mm`; percent UI values are whole percents. |
| Comparison | `GREATER_THAN_OR_EQUAL`, `LESS_THAN_OR_EQUAL` | - | Matches values greater than or equal to, or less than or equal to, the supplied scalar on fields that support inclusive ordered comparison. | Use one scalar matching a field that exposes the operator. Date/date-time values use `DD/MM/YYYY` or `DD/MM/YYYY HH:mm`; percent values are whole percents. |
| Equality | `EQUALS` | - | Matches values equal to the supplied scalar. Strings compare case-insensitively, date and date-time fields match the same calendar day, and group fields match membership in the referenced group. | Use one scalar value from the live field definition. Date/date-time equality uses `DD/MM/YYYY` day matching. Group values use the group id or group id plus type shape exposed by the definition. |
| Equality | `DOES_NOT_EQUAL` | - | Matches values that are not equal to the supplied scalar, using the same field-specific comparison semantics as `EQUALS`. | Use the same value shape as `EQUALS`; do not encode the negation in the value. |
| String | `CONTAINS`, `STARTS_WITH`, `ENDS_WITH` | - | Matches strings that contain, begin with, or end with the supplied text, case-insensitively. | Use one string. Do not add regex wildcards yourself; the converter creates them. |
| Empty and null | `IS_EMPTY` | - | Matches absent values. String values also count as empty when the trimmed string is empty. | No value. Leave `condition.value` null or omit it. |
| Empty and null | `IS_NOT_EMPTY` | - | Matches values that are present, using the same field-specific emptiness rules as `IS_EMPTY` and inverting the result. | No value. Leave `condition.value` null or omit it. |
| Boolean | `IS_TRUE`, `IS_FALSE` | - | Matches boolean-like fields whose stored value is true or false after the field-specific value conversion. | No value in UI mode. Use only when the live field definition exposes the operator. |
| Membership | `ONE_OF` | - | Matches when the field equals any one of the supplied values. For group fields, matches membership in any referenced group. | Prefer comma-separated values for hand-authored JSON, for example `1,2,3` or `red,blue`, unless the live definition shows a different value shape. |
| Membership | `ANY_OF` | - | Matches tag fields that have any selected tag. | Use only when the live definition exposes it and the API accepts the tag field shape. |
| Membership | `CONTAINS_ONE_OF` | - | Matches text-like values that contain at least one supplied item. | Use a JSON-array value such as `["Socks","Underwear"]` unless the live definition shows a different value shape. |
| Contact status | `IS_{status}` | status: BLACKLISTED, NOT_CONFIRMED, SPAM_COMPLAINT, UNSUBSCRIBED | Matches the contact media status named by the operator. | No value. Use only on fields where the live definition returns the operator as supported. |
| Rolling previous time | `LAST_{unit}` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS, YEARS | Matches values in the rolling interval from N units ago up to now. | Use positive integer `N`; `0` creates an empty or effectively useless interval. |
| Future relative time | `NEXT_{unit}` | unit: MINUTES, DAYS, WEEKS, MONTHS, YEARS | Matches values in the rolling interval from now up to N units in the future. | Use positive integer `N` only when the exact `NEXT_*` operator is returned by the live definition. Use `NEXT_HOURS_RANGE` for hour ranges where exposed. |
| Relative before | `BEFORE_{unit}_AGO` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS, YEARS | Matches values on or before the cutoff N units ago. | Use integer `N`. Positive values mean on or before the point N units ago. |
| Previous relative time | `{unit}_AGO` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS, YEARS | Matches the single past time bucket N units ago, aligned to the relevant minute, hour, day, week, month, or year boundary. | Use integer `N`. `0` means the current bucket; positive values mean past buckets; negative values produce future buckets but should not be used for ordinary UI authoring. |
| Previous fixed time | `YESTERDAY`, `{period}_AGO` | period: WEEK, MONTH, YEAR | Matches a fixed previous bucket: yesterday, previous week, previous month, or previous year. | No value. Use the alias only when the live definition returns it. |
| Current calendar time | `TODAY`, `THIS_WEEK`, `THIS_MONTH`, `THIS_YEAR` | - | Matches the current calendar bucket: today, current week, current month, or current year. | No value. |
| Same-day previous time | `THIS_DAY_{offset}_AGO` | offset: WEEK, WEEKS, MONTH, MONTHS, YEAR, YEARS | Matches the one-day bucket for the same calendar day N weeks, months, or years ago. | Singular forms require no value. Plural forms use integer `N`. |
| Last rolling range | `LAST_{unit}_RANGE` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS, YEARS | Matches the rolling interval between two past offsets from now. | Use two comma-separated offsets such as `14,7`; order does not matter. Values mean "between N and M units ago". |
| Past offset range | `{unit}_AGO_RANGE` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS, YEARS | Matches the bucket-aligned interval between two past offsets. | Use two comma-separated offsets such as `15,10` or `4,2`; order does not matter. |
| Future offset range | `NEXT_{unit}_RANGE` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS, YEARS | Matches the interval between two future offsets from now. | Use two comma-separated offsets such as `3,7` or `2,5`; order does not matter. |
| Annual recurring date | `EACH_YEAR_{day}` | day: TODAY, YESTERDAY, TOMORROW | Matches the recurring month and day for today, yesterday, or tomorrow while ignoring the stored year. | No value. Use for birthday/anniversary-style checks where the stored year must be ignored. |
| Annual recurring date | `EACH_YEAR_IN_{unit}` | unit: DAYS, WEEKS, MONTHS | Matches a recurring day, week, or month bucket N units from the current date while ignoring the stored year. | Use integer `N`. Prefer `_BEFORE` UI operators for user-facing "before" wording instead of hand-authoring negative values. |
| Annual recurring date | `EACH_YEAR_NEXT_{period}` | period: DAYS, WEEK, MONTH | Matches a recurring forward window from today through the next N days, next week, or next month while ignoring the stored year. | `EACH_YEAR_NEXT_DAYS` uses integer `N`; `0` means today. `EACH_YEAR_NEXT_WEEK` and `EACH_YEAR_NEXT_MONTH` require no UI value. |
| Annual recurring date | `EACH_YEAR_AGO_DAYS` | - | Matches a recurring backward day window ending before today while ignoring the stored year. | Use integer `N`; positive values mean previous N-day recurring window ending before today. |
| Annual recurring date | `EACH_YEAR_IN_{unit}_BEFORE` | unit: DAYS, WEEKS, MONTHS | Matches a recurring day, week, or month bucket N units before the current date while ignoring the stored year. | Use positive integer `N`. |
| Annual recurring date range | `EACH_YEAR_{unit}_AGO_RANGE` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS | Matches the annual-recurring version of a past offset range while ignoring the stored year. | Use two comma-separated offsets; order does not matter. Use only on regular-date fields returned by the live definition. |
| Annual recurring date range | `EACH_YEAR_LAST_{unit}_RANGE` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS | Matches the annual-recurring version of a rolling last range while ignoring the stored year. | Use two comma-separated offsets; order does not matter. |
| Annual recurring date range | `EACH_YEAR_NEXT_{unit}_RANGE` | unit: MINUTES, HOURS, DAYS, WEEKS, MONTHS | Matches the annual-recurring version of a future offset range while ignoring the stored year. | Use two comma-separated offsets; order does not matter. |
| Streaks | `LAST_{unit}_STREAK` | unit: DAYS, WEEKS, MONTHS | Requires the aggregate rule to be satisfied for each consecutive day, week, or month interval in the last N periods. | Use positive integer `N`. Streaks are meaningful only in aggregate contexts that define the rule to be checked for every interval. |
| Streaks | `STREAK_{unit}_RANGE` | unit: DAYS, WEEKS, MONTHS | Requires the aggregate rule to be satisfied for each consecutive day, week, or month interval in the supplied date range. | Use a comma-separated date or date-time range using the same format as `BETWEEN`. |
